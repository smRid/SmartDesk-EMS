# Phase 7 attendance and shift schema proposal

## Time and trust model

- Punch timestamps are generated by PostgreSQL/`now()` and stored as `timestamptz` (UTC instant). The browser clock is never accepted as a punch time.
- `attendance_records.work_date` is the local calendar date on which the assigned shift starts. The shift carries an IANA timezone, defaulting to `Asia/Dhaka`, so overnight checkout remains attached to the prior work date.
- Display and schedule calculations use the stored timezone. The design remains valid for DST-observing zones even though Asia/Dhaka currently has no DST transitions.
- GPS, biometrics, IP-derived location, and device fingerprinting are not collected. Enabling any requires a separate documented business purpose, retention policy, consent/privacy review, and schema change.

## Additive tables

- `work_shifts`: name, timezone, local start/end times, grace minutes, scheduled weekdays, overnight flag, active state.
- `shift_assignments`: employee, shift, effective date range. A PostgreSQL exclusion constraint prevents overlapping assignments for an employee.
- `attendance_records`: employee, assignment/shift snapshot, local work date, trusted check-in/out instants, computed minutes, late minutes, and record status. Unique `(employee_id, work_date)`; a partial unique index prevents more than one open record per employee.
- `attendance_events`: immutable check-in/check-out event log with a client-generated idempotency key. Unique event key makes retries safe.
- `attendance_adjustments`: employee correction request with requested timestamps, reason, status, reviewer note/actor, and timestamps. Decision history is retained in `audit_logs`.

## Indices and concurrency

- Employee/date and status/date indices support daily/monthly dashboards.
- Shift-assignment date-range exclusion prevents ambiguous schedules.
- Check-in and checkout use conditional writes plus unique constraints. Repeated idempotency keys return the already-applied result; concurrent duplicate punches cannot create two open sessions.
- Correction approval updates the target record and request in one Neon HTTP batch, guarded by a conditional pending-state update.
- Holiday dates reuse `holiday_calendar`; holidays can be shown as non-working days without duplicating the source of truth.

## Attendance rules

- A missing active assignment blocks check-in and directs the employee to HR.
- Late minutes are measured from scheduled local start plus grace time.
- Checkout calculates worked minutes from trusted instants and supports overnight shifts.
- Inactive accounts/employees cannot punch or request corrections.
- Corrections never rewrite immutable punch events; they update the derived attendance record and preserve request/audit history.
